THE ORDER MATTERS

A design document is read by someone who has never met you. It has to go from big to small — the feeling first, then the rules, then the details. Write it in this order:

1. What this is

one or two sentences. What is ROLLER, and what are you changing about it?

2. The feeling

your AESTHETIC, and why you picked it

3. The rules

your two MECHANICS, each with its trigger, what changes, and its tuning number

4. What will happen

the DYNAMICS you predict, and the one you are least sure about

5. How it works inside

your state map for the mechanic you build first

6. What I build first

one sentence naming the smallest piece you would start with

I DO — WHAT SECTION 3 LOOKS LIKE FINISHED

This is the level of detail every mechanic needs. Short, but nothing left to guess.

RULE

A block falls away two seconds after the player stands on it, then comes back three seconds later.

TRIGGER

The player's feet touch the top of the block.

WHAT CHANGES

A black dot appears on the block while it is about to fall. Then the block disappears and the player falls through.

TUNING NUMBER

How many frames it shakes before falling. Starts at 120, which is about two seconds.

WHY IT IS HERE

It creates tension, because you cannot stand still and plan.

Notice the last row. Every mechanic has to earn its place by pointing back at your aesthetic. A mechanic that does not is a mechanic you should cut.

PUT IT ON YOUR SITE

Type your real answers into the ANSWERS tab of the Google Doc, not into this handout. Then these six steps.

1. Select the ANSWERS tab

Click it in the tab list on the left so it is the tab you are looking at. This matters — the download only takes the tab you are on.

2. Download it as a web page

File → Download → Web Page (.html, zipped).

If a box asks you which tabs, choose Current tab — NOT All tabs. You only want your answers, not the instructions.

Do not download from the Google Drive homepage.  Right-clicking the file in Drive gives you a Word file of the whole document, instructions included. Download from inside the doc, from the File menu.

3. Unzip it

You get a .zip. Open it and pull the files out. Inside is one .html file. If there is also an images folder, keep it — it has to travel with the html.

If you don’t know how to do that on a chromebook, you can use this tool:  https://9-7-8.github.io/SmallPages/unzip.html 

4. Rename the html file

Call it exactly:

filename

roller-mod-design.html

All lowercase, dashes not spaces. This becomes part of your web address, so a name with spaces in it will break the link.

5. Upload it to your portfolio repo

Drag the html file (and the images folder, if you got one) into your portfolio repo on github.com. Commit it.

6. Link it from your home page

Open your index.html and add a link so people can find it:

<a href="roller-mod-design.html">My ROLLER Mod Design</a>

Commit, then open your live site and click the link. Press Ctrl + Shift + R if it does not show up — check that before you change anything.

STUCK?

•  Your file has the instructions in it too? You downloaded the wrong tab, or picked All tabs. Click the ANSWERS tab and download again.

•  Got a Word file instead of a zip? You downloaded from Drive. Do it from the File menu inside the doc.

•  Cannot find your portfolio repo? It is the one with your class website in it. Ask me and I will point at it.

•  A section is empty because you never wrote that part? Write it now. That is the real work of today.

•  A mechanic has no “why it is here”? Either connect it to your aesthetic or cut it. Both are fine answers.

•  Document feels too short? Short is fine if nothing is missing. Length is not the standard — completeness is.

•  Link goes to a 404? Check the filename matches exactly, including lowercase and the .html on the end.

•  Pushed but cannot see it? Press Ctrl + Shift + R on the GitHub page. Check that before anything else.

•  Ask me to say it again. Check your MDA reference packet. Take a break if you need one.
